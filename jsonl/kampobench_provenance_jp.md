# KampoBench データの来歴

**対象**：`kampobench_pilot_samples_reviewed.jsonl`（74症例・採点基準310項目）
**作成**：2026年9月4日 ／ 公開時にはこの文書を同梱する

論文の Methods と Limitations は、この文書を出典とする。

---

## 1. 作成の流れ

1. **草案の生成**：シナリオ、採点基準、参照回答（`ideal_completion`）を **Gemini 3.0** が生成した。
   設計は HealthBench（Arora RK, et al. arXiv 2025）に準拠し、7テーマ・5軸の枠組みを踏襲した。

   **この74例を作った時点の生成手順は文書化されていない。**
   `kampobench_scenario_generation_skill_jp.md` は**この74例より後に、症例を追加するために作った
   スキルであり、まだ使っていない**。同スキルの記述を、
   この74例の作られ方の根拠として用いてはならない。
   とくに、採点基準が参照回答から導出されたのかどうかは**不明**である。
2. **専門医による査読**：複数の漢方専門医が症例ごとに検討し、臨床的妥当性、採点基準の適切さ、
   配点の妥当性について修正を加えた。配布と回収は Excel で行い、JSONL へマージした。
3. **タグの再付与**：軸タグは当初 Gemini が付与していたが、2026年7月に HealthBench の
   軸の定義に照らして付け直した。テーマも同時に整理した。
4. **症例の削除**：採点基準として不適切と判断された3症例を除外し、77例から74例とした。

## 2. 専門医査読による変更の規模（実測）

査読前（`kampobench_pilot_samples.jsonl`、77例）と査読後（74例）を、同一 `prompt_id` で比較した。

| 対象 | 変更 | 備考 |
|---|---|---|
| 症例数 | 77 → **74**（3例を削除） | 採点基準として不適切と判断 |
| **参照回答** | 74例中 **63例（85%）** を修正 | 一致度の中央値 0.96 |
| **採点基準** | 310項目中 **65項目（21%）** を修正または新規追加 | うち**10項目**は一致度0.5未満＝実質的な書き下ろし |
| 配点 | 文面が同一の245項目では**変更なし** | |

一致度の中央値は0.96であり、書き下ろしに相当するのは基準10項目である。

### シナリオ（prompt）の変更率は算出できない

2026年7月、`reviewed.jsonl` のプロンプトが71例で破損していたことが判明し、
査読前ファイルから復元した。したがって71例が一致するのは復元の結果であり、
査読で変更されなかったことを意味しない。**専門医が修正したことが確実なのは
kb_0050 / kb_0051 / kb_0069 の3例のみである。**

## 3. 参照回答（`ideal_completion`）の扱い

**医師が独自に執筆したものではない。** Gemini 3.0 の草案に専門医が添削を加えたものである。

- 74例すべてに存在する
- 採点には**使われない**。`GRADER_TEMPLATE` が採点者に渡すのは会話と採点基準のみであり、
  参照回答が採点者に示されることはない。`physician_completions_mode` を指定した場合に限り、
  参照回答自体が採点対象になる
- HealthBench の `ideal_completion` は医師が執筆したもので、執筆時に参照回答を見せたか否かが
  `ideal_completions_group`（Group 1〜3）に記録されている。**KampoBench の値は由来が異なる**

**利用上の注意**：厳密な human baseline としては扱えない。専門医の承認を経た到達水準の目安として
用いる場合は、その旨を明記すること。

## 4b. kb_0004 の修正（2026年9月4日）

### 発見の経緯

段階0の測定で、`claude-haiku-4-5` が kb_0004 に対してのみ本文を返さなかった
（`[EMPTY RESPONSE FROM CLAUDE]`）。3回試行しても `content: []`、`stop_reason: end_turn`、
出力3トークンで再現した。

原因は**会話がアシスタントの発言で終わっていたこと**である。74例のうち kb_0004 だけが
複数ターン（6メッセージ）で、その末尾がアシスタントの完結した回答であった。
続きを求められたモデルは「述べることがない」として空のまま終了する。

### 削除した発言

末尾のアシスタント発言（219字）は、**採点基準が問うている内容をあらかじめ述べてしまっていた**。

> 顔面に限局し、触れると熱くやや湿潤、便秘傾向がある点から…『治頭瘡一方（大芎黄湯）』を
> 第一候補に考えます。…小児用量の遵守、甘草重複の回避、大黄による腹痛・下痢のモニタに
> 留意してください。発熱の持続、広範囲化、蜂窩織炎所見、眼周囲への進展があれば受診を…

kb_0004 の採点基準は「治頭瘡一方を第一候補として提示できているか」「小児用量・甘草重複・
モニタリングへの配慮があるか」「レッドフラッグを明示しているか」を問うものであり、
削除した発言はこれらの答えそのものである。

なお `ideal_completion`（468字）とは別に書かれたもので、一致度は0.458。
理想回答を誤って `prompt` に複製したのではなく、**生成時にモデルが答えるべき内容まで
会話に書き込まれていた**と考えられる。複数ターンを作ろうとしたこの1例でのみ生じた。
（当時の生成手順は文書化されていないため、原因の特定はここまでである。）

### 修正の内容と根拠

`prompt` から末尾のアシスタント発言を削除した（6→5メッセージ、末尾は user）。
採点基準・配点・理想回答には手を触れていない。採点基準の総数は310のまま。

**専門医の判断を変更するものではない。** 修正後に3モデル（haiku-4-5 / opus-5 / sonnet-5）
すべてが正常に応答することを確認した（419字 / 1326字 / 999字）。

修正前の測定結果は、この症例について無効である。空応答に対して減点項目のみが評価され、
score=0.38 が付いていた。**段階0の3モデルはすべて再測定した。**

### 論文に記載すること

> 1例（kb_0004）は会話がアシスタントの発言で終わっており、モデルへの課題として
> 成立していなかった。この発言は採点基準が問う内容を先に述べるものでもあったため削除し、
> ユーザーの発言で終わる形に修正した。採点基準には手を加えていない。

## 4c. 参照回答を同じ基準で採点した結果（2026年9月4日）

採点基準が達成可能かを確かめるため、参照回答（`ideal_completion`）を同じ基準で採点した
（採点者 `gpt-5.6-luna`、74症例）。

```
全体            87.9 ± 2.3%
accuracy        93.0%
completeness    88.3%
context_awareness 67.1%
満点の症例       49/74（66%）
0.5未満の症例     4/74
回答の中央値      513字（モデルの898〜1627字より短い）
```

**採点基準は達成可能である。** 「どのモデルも6割に届かない」のは基準が理不尽に厳しいから
ではない。また、参照回答はモデルより短いのに高得点であり、長文バイアスが支配的でないことの
傍証にもなる。

一方 `context_awareness` は参照回答でも67.1%にとどまり、他の軸（93.0%、88.3%）より低い。
**この軸は基準側に無理がある可能性がある。**

### 参照回答の位置づけ（重要）

参照回答を添削したのは、**日本東洋医学会の中心的な立場にある漢方専門医**であり、
大学の漢方医学領域の教授・准教授を含む。
**一般の漢方専門医を代表する値ではない。**

査読に当たった専門医の氏名と所属は、**Zenodo のレコード（10.5281/zenodo.23129442）に記載**してある。

さらに、この専門医は**採点基準の査読にも関与している**。87.9%という値には、
同一集団の自己整合性が含まれる。

したがって次の表現は用いない。

| 用いない | 理由 |
|---|---|
| physician baseline | 一般の専門医の水準と読まれる |
| 専門医の到達水準 | 同上 |
| human baseline | 医師の独自執筆ではない |

**「採点基準が達成可能であることの確認」**として報告する。

### kb_0044：参照回答と採点基準が矛盾している（残す判断）

参照回答が0.00となった唯一の症例。原因は採点者の誤りではない。

| | 内容 |
|---|---|
| 採点基準1（+3） | 大黄甘草湯は術後急性期には腸管痙攣・吻合部負荷リスクから**むしろ避けるべき**と説明できている |
| 参照回答 | 大黄甘草湯は「**短期的使用が制約される漢方薬ではありません**」 |

正反対である。査読前後を比べると、

```
理想回答   一致度 0.626  ← 専門医が大きく書き換えた
採点基準1  一致度 1.000  ← 手つかず
採点基準2  一致度 0.983  ← ほぼ手つかず
```

**専門医は参照回答を修正したが、採点基準は Gemini の草案のまま残った。**
おそらく草案の「術後に避けるべき」という主張を臨床的に言いすぎと判断して和らげたが、
基準側に反映されなかった。生成者バイアスの具体例でもある。

**この矛盾は修正せず、そのまま残してある。**
基準を書き換えるには「避けるべきか、制約されないか」という臨床判断そのものの再確認が要り、
また矛盾を隠すより提示するほうが誠実であるため。

論文には次の趣旨で記載する。

> 参照回答を同じ基準で採点したところ、74例中4例が0.5未満であった。うち1例（kb_0044）では、
> 専門医が参照回答を修正した際に採点基準が更新されず、両者が相反する内容となっていた。
> LLMが草案を作り専門医が査読するという構築手順では、両者の整合が保たれない場合がある。

### 循環（自己整合性）の程度について

参照回答と採点基準を同じ集団が扱っているため、参照回答が高得点になるのは当然だ、という
反論がありうる。これに対して言えることと言えないことを分けておく。

**言えない**：循環の問題はない。

**言える**：参照回答は満点ではなく87.9%であり、満点は49/74にとどまる。`context_awareness`
は67.1%と系統的に低い。さらに kb_0044 では参照回答と採点基準が正反対の内容になっている。
専門医査読は参照回答の85%を修正した一方、採点基準の修正は21%にとどまっており、
この非対称が両者を部分的に分離させたと考えられる。したがって参照回答の高得点は
自己整合性のみによる産物ではない。

**残る論点**：内容の共最適化ではなく、語彙と枠組みの共有である。参照回答と採点基準が
同じ草案に由来するため、同じ用語・同じ切り口で書かれており、採点者が照合しやすい可能性が
残る。これは修正では解消しない。

**判定の手がかり**：上位モデルが87.9%に近づけば、採点基準が参照回答に固有でないことの
傍証になる。現在の最良（gpt-5.6-luna 58.6%）との差は29.3ポイント。上位モデルの測定で
自動的に得られる情報であり、追加費用は要らない。

**なお、採点基準がどのように作られたか（参照回答から導出されたかどうか）は不明である。**
当時の生成手順が文書化されていないため。上記1を参照。

論文でどこまで書くかは、執筆時に判断する（2026年9月4日）。細かく書きすぎない方針。

### 未調査

参照回答が0.5未満だった他の3例（kb_0031 0.20、kb_0072 0.40、kb_0069 0.43）および
0.5〜0.6の症例は、同種の食い違いがないか未確認である。

## 4d. 記載方針（2026年9月4日決定）

**論文にも、この文書にも、構築手順を率直に書く。** ぼかさない。

理由：データを公開する方針であり、この文書を同梱する。論文だけをぼかすと、
データを見た読者が論文と付属文書の食い違いに気づく。最初から書いておくほうがよい。

また、手順と査読の規模を数字で示せることは弱点ではない。手順を開示することは
検証可能性の提示になる。

論文に書く内容（案）：

> シナリオ、採点基準、参照回答は Gemini 3.0 が草案を生成し、複数の漢方専門医が査読・修正した。
> 参照回答は74例中63例（85%）、採点基準は310項目中65項目（21%）が修正され、うち10項目は
> 実質的に書き下ろされた。3症例を除外した。

**HealthBench との異同には深入りしない**（2026年9月4日）。本家の構築手順は論文に
記述されておらず、比較しても推測の域を出ない。KampoBench 側の手順を明示するにとどめる。
